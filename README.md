# Citizen Human Capital — website and test intake APIs

Responsive, locally hosted front-end implementation of the supplied About Us copy, Contact details, Conferences, Training Courses, Audience Marketing multi-sector RPL and External HR Management pages, and homepage visual system. Built with semantic HTML, CSS and JavaScript modules using Vite, plus gated Express test intake APIs for driver applications and employer enquiries. DM Sans and Lato are bundled locally (no third-party font requests).

## Run

```sh
npm install
npm run dev
npm run build
npm run preview
```

The development server binds to `0.0.0.0`. `/` and `/about` show the About page. `/about/our-purpose`, `/about/our-team` and `/about/sustainability` resolve to the corresponding sections. Serve generated documents for `/services/rpl`, `/services/external-hr-management`, `/services/driver-recruitment`, `/popia-notice`, `/code-of-conduct`, `/apply` and `/employers` (including trailing slash/query variants) **before** applying the SPA fallback to other non-file routes. Proxy `/api` to the protected Express intake service; a static-only host cannot receive applications or enquiries. The build output is `dist/`.

### Storage and operational boundary

`server/app.js` accepts `POST /api/applications` as multipart data: one JSON `answers` field, up to seven files named by category, and a UUID `Idempotency-Key` header. All answers, conditional fields, permissions, file limits and signatures are checked again server-side. The response is issued only after the encrypted bundle is written, synced, atomically renamed and the directory synced. A matching retry returns the original receipt; changing contents under an already-used key returns 409. This is request idempotency, **not** ID-number deduplication.

The bundle contains actual file bytes (base64 within the encrypted record), normalized answers, notice version, explicit processing/marketing choices and receipt. AES-256-GCM uses a fresh IV per record; filenames derive from a keyed hash of the request identifier, not candidate IDs/names. The directory is 0700 and files 0600. Test mode creates a private `.test-key`; production requires a 32-byte hex key from protected host configuration. Default test storage is `../.citizen-application-data`, **outside** the website repository. Storage inside the site repository is rejected, and Vite denies encrypted/key paths. Do not serve the data directory, scanner temporary directories or backups through the web server. Test data is not a repository artifact.

The API has no public record-list, read, update, document-download or ID-lookup endpoint. Staff access currently means authorised **host/OS access**, not a completed browser-based recruitment dashboard. No notification email, messaging service, staff SSO, candidate authentication, database-wide ID matching, automatic retention job or cross-process locking is implemented. This is a **single-process, single-instance** disk-backed intake; do not deploy multiple workers/replicas sharing its directory. Use a transactional database/object-store design before scaling. Rate limiting is process-local. Encryption at rest is not end-to-end encryption or a claim of legal compliance; the application host and authorised operators can decrypt records.

Live mode requires exact HTTPS `APP_ORIGIN`, at least one explicitly enabled intake (`APPLICATIONS_ENABLED=true` and/or `ENQUIRIES_ENABLED=true`), an approved notice version, an external absolute data directory, the encryption key and an absolute ClamAV-compatible `APPLICATION_SCANNER` executable. Each live upload is scanned in a private temporary directory with a timeout, and any scanner failure prevents acceptance. Test mode does not run antivirus and must never accept real records. Set the exact trusted proxy hop count, keep the API port private behind the same-origin HTTPS frontend, limit request bodies to roughly 36 MB and apply upstream request/concurrency/time/rate limits. Review infrastructure access/request logging to avoid sensitive payloads. The app does not log answers or filenames. In-memory uploads are bounded per request (7 × 5 MB); concurrency controls and an upstream memory budget still need load/security testing. MIME signatures are only a preliminary format check, not a content safety guarantee.

### Host-only staff operations

Use the protected host environment for `APPLICATION_DATA_DIR` and `APPLICATION_ENCRYPTION_KEY`. Restrict shell access and audit the host. The management utility records operator username, timestamp, action and reference in a private `.operations.jsonl`; it does not print IDs or document contents in normal listings. These logs are not tamper-proof and do not replace a production access-audit system.

```sh
node server/manage.js list
node server/manage.js export CHC-REFERENCE --output /private/chc-export/record.json
node server/manage.js delete CHC-REFERENCE --confirm
# Only after retention policy approval; no period is assumed:
APPLICATION_RETENTION_DAYS=<approved-days> node server/manage.js purge --confirm
```

Replace `CHC-REFERENCE` with a genuine issued reference. Export requires a private (0700) directory outside the repository and creates a new 0600 JSON file containing sensitive answers and base64 documents; it refuses overwrite. Exports and backups need their own retention, access and deletion controls. Delete/purge remove primary bundles only. Driver purging uses `APPLICATION_RETENTION_DAYS`; employer purging separately requires `ENQUIRY_RETENTION_DAYS`. A missing policy skips that record type. Use `--test` explicitly to operate on local fictional records and load the test key. Arrange review ownership, a secure correction/identity-verification process, tested restore/key recovery, approved retention schedules and controlled handoff before opening live intake. No automatic notification is sent when a record arrives: an approved staff review/monitoring workflow is a launch requirement.

### Device privacy and truthful state

Draft storage is **off by default**. Opt-in saves normalized answers (including SA ID) and file metadata only after 400ms. It expires on next visit after seven days, not via a guaranteed background deletion timer. It restores the step, radios, checkbox groups and branches, but never file bytes or consent choices. Reselect files after reopening; review explicitly marks them unattached. Storage failures do not stop in-memory use. Clearing a saved draft retains the current on-screen answers until navigation; starting a new application resets all answers, files, branches and errors. Browser localStorage is not encrypted and is inappropriate for a shared phone. Clearing this site’s storage or a shared-device receipt does not delete server records.

Success requires a valid accepted API response with a server-issued reference. A lost response shows “receipt could not be confirmed”, not a fake failure/success. An unchanged explicit retry uses the same request key. The device receipt has only reference/mode/time, is not a global duplicate-ID result, and may belong to another device user. Update requests go to confirmed reception, with no sensitive documents requested by email. WhatsApp remains absent until its number and operational process are confirmed.
